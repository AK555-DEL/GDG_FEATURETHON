# GDG FEATURETHON'26

Organised by **Google Developer Groups (GDG), Gokaraju Lailavathi Engineering College**

Explore an existing web application, identify a genuine user problem, propose an innovative improvement, and implement a meaningful feature or working prototype to demonstrate to the jury. The challenge is to improve the application, not rebuild it from scratch.

## Event format

Thirty individual participants take part and are randomly assigned to one of three projects, with approximately 10 participants per project. Participants cannot choose their project or presentation order. They compete only against participants assigned to the same project. One winner is selected from each project, for three winners in total.

## Event rules

- The event starts at **9:00 AM sharp**. Registration closes at **9:30 AM**.
- Participants must remain at the venue except for emergencies, medical needs, or short breaks with a coordinator's permission.
- Follow coordinator instructions throughout the event.
- Maintain discipline and ensure fair opportunities for everyone.

## What participants will do

1. Explore the assigned application and understand its existing functionality.
2. Identify genuine user problems, gaps, or limitations.
3. Propose a practical and innovative improvement.
4. Implement a meaningful feature or working prototype.
5. Demonstrate how the improvement benefits users.

Participants do not need to rebuild the application, and a production-ready implementation is not required. The implementation should demonstrate a meaningful improvement rather than a purely theoretical idea.

## Presentation

Each participant has **5 minutes** for their presentation and demonstration, followed by **2 minutes** of jury questions. Present:

- The problem you identified.
- Your proposed solution.
- The feature or prototype you implemented.
- How your improvement benefits users.

## Judging criteria and winner selection

Each judge scores every participant from 1 to 5 in each category, for a maximum of 25 points per judge.

| Category | What is evaluated |
| --- | --- |
| Problem Identification & Purpose | How clearly the participant identifies a genuine user problem and explains its importance |
| Innovation & Originality | Creativity and uniqueness of the proposed solution |
| Technical Depth & Implementation | Quality and functionality of the implemented feature or prototype |
| User Experience & Feasibility | Practicality, usefulness, and ease of use |
| Presentation & Demonstration | Clarity of the explanation and effectiveness of the demonstration |

| Score | Description |
| --- | --- |
| 5 | Exceeds one or more brief goals in an innovative way |
| 4 | Moderately exceeds one or more brief goals |
| 3 | Meets one or more brief goals |
| 2 | Nearly meets at least one brief goal |
| 1 | Does not meet any brief goal but receives a participation point |

Each project is evaluated separately. The participant with the highest average total score across the judges evaluating that project wins. Exactly one winner is selected per project.

Tie-breakers:
1. Higher average Technical Depth & Implementation score.
2. If still tied, higher average Problem Identification & Purpose score.
3. If still tied, the head judge makes the final decision.

## Common prerequisites

- [Git](https://git-scm.com/install/) to clone the assigned project.
- [Node.js](https://nodejs.org/en/download). Node.js 24 LTS is compatible with the published requirements of all three projects; check the assigned project's guide for its exact requirement.
- npm, included with Node.js. PancakeMaker requires npm 10.9.0.
- A modern web browser. [Google Chrome](https://www.google.com/chrome/) and [Visual Studio Code](https://code.visualstudio.com/download) are optional.
- On Windows, use PowerShell and the `npm.cmd` commands in the setup guides. On macOS or Linux, use `npm` instead of `npm.cmd`.

## Participant workflow

1. Check your assigned project and open its setup guide.
2. Install the required software.
3. Clone the original project repository locally.
4. Install dependencies and start the application.
5. Explore the application and understand its existing functionality.
6. Identify a genuine user problem, gap, or limitation.
7. Brainstorm an innovative, practical improvement.
8. Develop a meaningful feature or working prototype. A production-ready implementation is not required.
9. Prepare your presentation and demonstration.
10. Present your work to the jury.

Each participant works on their own local clone of the assigned project. GitHub submission is not required. Local Git commits are optional.

Never commit `.env` files, API keys, passwords or other secrets.
